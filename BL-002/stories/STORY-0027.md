# STORY-0027 — Open Customer Consumption Dashboard at Root Route

- Release: R2
- Endpoint: `GET /customer-consumption`
- Controller: `CustomerConsumptionDashboardController.dashboard`
- Approval: PENDING_USER_APPROVAL
- Enrichment state: STRICT_FIELD_UI_COMPLETE
- Frozen source: `CylinderManagement@3ae6e61442132d94a307275b08dd65fcef228d89`

The user opens `/customer-consumption`. `CustomerConsumptionDashboardController` is mapped at `/customer-consumption`, and its `dashboard` method accepts `GET` on `""`, `/`, and `/dashboard`, so this root route enters the same source-proved dashboard flow as those aliases. Spring binds query values into `CustomerConsumptionSearchRequestDto`. The DTO accepts `customerId`, `productId`, `projectionStatus`, `forecastConfidence`, `pageNumber`, `itemsPerPage`, `sortField`, `sortDirection`, `expectedNeedDateFrom`, and `expectedNeedDateTo`; constructor defaults are page 1, 25 rows, sort field `expectedNeedDate`, direction `asc`.

The visible Thymeleaf screen is `with-menu/CustomerConsumptionDashboard`. Its GET filter form posts no data writes: it submits back to `/customer-consumption/dashboard`. Visible controls are Customer Id (`customerId`, number, min 1), Product Id (`productId`, number, min 1), Expected Need From (`expectedNeedDateFrom`, date), Expected Need To (`expectedNeedDateTo`, date), and Rows (`itemsPerPage`, number, min 5, max 100). Hidden values are `pageNumber=1`, `sortField`, and `sortDirection`. `Apply Filter` is an ordinary submit button; this template contains no page-local JavaScript, debounce, minimum typing length, dependent API call, or dynamic enable/disable rule.

The controller calls `CustomerConsumptionDashboardService.fetchDashboard(requestDto)`, then exposes `requestDto` and `dashboardDto` to the model. The service sanitizes page number to at least 1, items-per-page to default 25 when missing/less than 1 and caps it at 100, swaps the two expected-need dates when From is after To, defaults blank sort to `expectedNeedDate`, and normalizes direction to `asc` unless explicitly `desc`. Sort names map exactly as follows: `customerName -> customerName`, `productName -> productName`, `lastDeliveredAt -> latestDeliveredAt`, `currentCylinderCount -> activeHoldingCylinders`, `consumptionDaysPerCylinder -> avgConsumptionDaysPerCylinder`, `previousDeliveredAt -> oldestDeliveredAt`, and `expectedNeedDate` or an unknown value -> `projectedEmptyAt`.

Filtering is read-only through `CustomerProductConsumptionProjectionViewJpaDao` using a JPA Specification: optional customer equality, optional product equality, projected-empty timestamp >= Expected Need From at start of day, and projected-empty timestamp < the day after Expected Need To at start of day. Paging is zero-based internally (`pageNumber - 1`). The immutable projection entity reads `public.vw_customer_product_consumption_projection` through a Hibernate `@Subselect`, generating `projection_row_id` with `ROW_NUMBER()` ordered by customer, address and product. The entity declares synchronization with `tbl_cylinder_party_custody`, `tbl_cylinder`, `tbl_product`, and `tbl_customer`; this dashboard path performs no persistence write.

Each result is mapped to the customer/product projection DTO. The screen renders Customer, Product, Last Delivered Date, Current Cylinders, Consumption Days / Cylinder, Expected Need Date, and Previous Delivery. Null date/text display values are converted by the mapper to `-`; current cylinder count null becomes 0. The mapper derives `currentCylinderCount` from `activeHoldingCylinders`, `lastDeliveredAt` from `latestDeliveredAt`, `previousDeliveredAt` from `oldestDeliveredAt`, `consumptionDaysPerCylinder` from `avgConsumptionDaysPerCylinder`, and `expectedNeedDate` from `projectedEmptyAt`. The screen explicitly explains that 0 consumption days means first delivery/no previous delivery.

The summary is also read-only: total customer/product rows uses repository count; current cylinders sums active holdings; First Delivery counts status `FIRST_DELIVERY`; Need Now counts status `NEED_NOW`; average days/cylinder averages positive non-null `avgConsumptionDaysPerCylinder` and rounds to two decimals. The UI displays those five KPI values.

Clicking a sortable column issues another GET, preserves current filters and row count, resets page to 1, and toggles asc/desc for that column. Previous/numbered/Last/Next pagination links preserve filters and sort state. Previous or Next is rendered disabled when the corresponding page is unavailable. If the projection list is empty the table displays exactly `No customer/product delivery rows available.` Otherwise rows and page/total counts are rendered from `dashboardDto`. No controller-local error catch or mutation branch exists for this GET. No approval occurred.
