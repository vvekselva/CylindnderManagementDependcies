# BL-004 — Approved Story Unit Test Generation

Purpose: generate and execute JUnit unit tests for every explicitly user-approved BL-002 Story.

## Entry gate
A Story enters BL-004 only when explicit user approval is durably evidenced in BL-002 and post-approval code conformance passes. Approval is never inferred or generated by the orchestrator. A Story with detected code drift remains held until the exact drift/code-change manifest is explicitly approved.

## Required outputs per approved Story
- `BL-004/stories/<story-id>.md` — human-readable unit-test contract.
- `BL-004/generated-tests/<story-id>/*Test.java` — JUnit 5 test source derived only from the approved Story/frozen source.
- `BL-004/unit-test-task-queue.csv` — dispatch/status projection.
- durable execution evidence after tests are actually executed.

## Test standard
Use JUnit 5. Use Mockito only for genuine unit boundaries. Cover positive, negative, branch and boundary behavior proved by the Story. Database collaborators are mocked/stubbed in BL-004; real PostgreSQL belongs to BL-005 Testcontainers integration testing.
